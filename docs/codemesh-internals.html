How the tools work and connect

Every tool is a handler over one SQLite graph. MCP (server.ts) and CLI (cli.ts) call the same handlers. Tools link through stable IDs and content hashes.

1 · The shared language

Stable IDs are how tools hand off

repo→ dir:src/auth→ file:src/auth/login.ts→ symbol:src/auth/login.ts:Auth→ symbol:…:Auth.login
concept:<targetId>:<sha256(summary)[0..16]> workflow:<kebab-name>

repo and dir: are virtual, built from indexed file paths. Nesting comes from qualified names: children of Auth are names starting Auth. with no further dot.

2 · Tool link map

What each tool hands to the next

Every box reads SQLite. source, inspect, hydrate and recall also hash the live file on disk before trusting the index.

3 · Freshness check

Three hashes guard every source read

file hashwhole file at index time bodyHashsymbol's line span sourceHashthe rendered view (mode-specific)

Missing file → deleted. force: true skips the ifHash shortcut, used after context compaction. Bytes delivered and avoided are counted in context_metrics.

4 · Source views

Four ways to render one symbol

full
Default. Exact body. Use for edits.
auto
Full if ≤ 120 lines and ≤ 12 KiB. Else head 12 + tail 8, whole lines only, omitted ranges listed.
preview
Full if ≤ 24 lines. Else first 12 + last 8.
fold
Signature + stored summary only.

Name lookup: exact ID → unique qualified name → unique .method suffix → else Ambiguous error listing up to 20 candidate IDs. It never guesses.

5 · Search ranking

Exact names first, fuzzy last

0Exact name match · login = loginexact
1Exact leaf of qualified name · Auth.loginexact_leaf
2FTS5 BM25, Porter stemming · tokens OR-joined over name, signature, summary, descriptionfts
3Trigram substring · only when FTS returns < 5 hitstrigram

Inside a tier: query-term coverage → BM25 rank → PageRank (or exactTieBreak: "path-depth"). path filters before caps. Results cached in SQLite retrieval_cache, keyed by graph version, so re-index invalidates them. Defaults: 20 hits, 8 KiB.

7 · Note lifecycle

How a note goes stale

Session 1enrich saves note + targetHash
EditSomeone changes the file
IndexNew file hash, old notes marked stale
Session 2recall returns note as stale: verify in source

Notes are never treated as code facts. A stale note is a clue, not evidence.

8 · Known gaps in current code

Limits to know

extendsAccepted by map, but no parser emits these edges, so it returns nothing.
importsOnly relative paths (./x) resolve. Package imports and TS path aliases create no edges.
trace orderSteps are sorted by PageRank, not call order.
inspectVerified call binding is Python-only. Other languages return unverified graph candidates.
re-indexChanged files are deleted and re-inserted, which can drop the edges that link old notes to them.
